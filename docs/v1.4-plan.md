# strive-sync 1.4.0: trust fixes

Status: next release. Bash only, on the current `bin/strive-sync` and `lib/*.sh`. Why this release exists: decision 0008.

Goal: `strive-sync` never reports success it didn't verify, never changes work it shouldn't, and gives scripts something reliable to read. No new features beyond that.

Line numbers refer to v1.3.0 (`9d27bee`); check them before editing.

Progress (branch `fix/v1.4-installs`): fixes 1, 2, 5 and 6 done, 3 done for installs and merge, 7 done for lockfile detection (saved commit instead of `HEAD@{1}`, `bun.lock`). Subfolder entries install in their own folder (SPEC 5.2 Grouping). Fixtures: `test/v1/run.sh`.

## Fixes

| # | Problem | Fix |
|---|---|---|
| 1 | The nvm switch does nothing: `lib/common.sh:87` runs `nvm use` in a subshell, so installs use the default Node. | Run `nvm use` in the same shell as the install. |
| 2 | Yarn 2+ installs fail: `yarn --silent --non-interactive` exits 1 (YN0050). | Detect yarn 2+ (`.yarnrc.yml`, or `packageManager: yarn@2+`) and run `yarn install --immutable`. |
| 3 | Exit codes are never checked: installs (`bin/strive-sync:267-283`) and `merge --ff-only` (`:225`) always report SUCCESS. | Check every exit code; show `FAILED` with the log path, and keep logs after the run. |
| 4 | A repo on a feature branch with no pin is compared with, and can be fast-forwarded to, `origin/<default>` (`:202-225`). | Never touch the feature branch. Update the local default branch with `git fetch origin <default>:<default>` when possible and report "on <branch>, <default> +N". |
| 5 | `npm install` can rewrite `package-lock.json`, the repo turns dirty, and every later run skips it. | Frozen installs only: `npm ci`, `pnpm install --frozen-lockfile`, `yarn install --frozen-lockfile` (yarn 1), `yarn install --immutable` (yarn 2+), `bun install --frozen-lockfile`. |
| 6 | A repo and a subfolder of it listed separately in `.repos` share one git root, fetch in parallel and clash. | Dedupe entries by `git rev-parse --show-toplevel`. |
| 7 | Always exits 0. Uses `HEAD@{1}` to detect lockfile changes. `bun.lock` not recognized. Ctrl-C runs cleanup twice. | Exit codes per SPEC section 2 (0, 1, 3, 130). Save the commit before merging and diff against it. Add `bun.lock`. Single cleanup (fix 15). |
| 8 | A pinned branch that isn't on the remote yet shows `FAILED Fetch error`. | New status `NOT PUSHED`, reported as information. |
| 9 | Pinned repos only fetch the pinned branch, so `origin/<default>` goes stale. | Fetch the default branch too. |
| 10 | No timing per repo. | Show each repo's duration. |
| 11 | `.repos` lines with inline comments break: `repo:main  # note` makes the branch `main  # note`. The README's own example fails. | Strip inline `#` comments (after whitespace), surrounding whitespace and CR. |
| 12 | Dry run never fetches and skips the diverged check (`:218`), so it reports SUCCESS on stale data. | Dry run fetches (only `origin/*` refs move), then predicts the real result, including `OUT SYNC`. |
| 13 | Ctrl-C: the INT trap runs cleanup, then the script keeps going (starts more workers, prints the summary twice); installs can be left running. | On INT/TERM: stop starting work, kill running children, print the summary once, exit 130. |
| 14 | The dashboard writes cursor-control codes even when stdout isn't a terminal. The `(ahead)` label is overwritten at `:236`. | Add `--plain` (one stable line per repo, no control codes), on by default when stdout isn't a terminal. Keep `(ahead)`. |
| 15 | Real company repo names appear in examples (`README_sync.md:100-102`, `bin/strive-env:30`). | Replace with neutral names (`api-service`, `web-app`). |

## Testing

1. `shellcheck bin/strive-sync lib/*.sh` is clean. Bash 3.2 compatible (macOS default).
2. A fixture script in `test/v1/` builds temp bare remotes and clones covering: clean and behind, ahead, diverged, dirty, feature branch, pinned branch not pushed, repo plus subfolder entry, `.repos` with inline comments, a failing install (fake package manager on PATH that exits 1). It checks each status and the exit code.
3. On real repos: dry run only (`strive-sync -d -y`), and only by the maintainer.

## Done when

- Every row above is fixed and covered by the fixture script.
- Exit codes match SPEC section 2.
- `--plain` output is stable enough for a script to parse.
- Release: tag `v1.4.0`; commit messages like `fix(sync): check install exit codes`.
